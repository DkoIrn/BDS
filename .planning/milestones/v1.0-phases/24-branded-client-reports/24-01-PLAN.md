1. Add a Pydantic model for the POST body:
   ```python
   from pydantic import BaseModel

   class ReportRequest(BaseModel):
       mode: str = "technical"
       triage_accepted: int | None = None
       triage_rejected: int | None = None
       triage_deferred: int | None = None
       sections: dict[str, bool] | None = None
       commentary: dict[str, str] | None = None
       brand_color: str | None = None
       logo_base64: str | None = None  # Base64-encoded logo bytes from proxy
   ```

2. Add a `POST /report/pdf/{run_id}` endpoint alongside the existing GET. The POST handler:
   - Accepts `ReportRequest` as JSON body
   - Performs the same run/issues/dataset fetch as GET
   - Builds triage_counts from body params (same logic as GET)
   - Builds branding dict: if brand_color or logo_base64 present, decode logo from base64 if provided (`import base64; logo_bytes = base64.b64decode(body.logo_base64)` if body.logo_base64 else None), construct `branding = {"logo_bytes": logo_bytes, "brand_color": body.brand_color}`
   - Passes branding, sections, commentary to generate_pdf_report
   - Returns StreamingResponse with PDF

3. Keep the existing GET endpoint unchanged for backwards compatibility. It calls generate_pdf_report without branding/sections/commentary (same as today).

4. Extract the shared fetch logic (run, issues, dataset_name) into a private `_fetch_report_data(run_id: str)` helper to avoid duplication between GET and POST handlers.
