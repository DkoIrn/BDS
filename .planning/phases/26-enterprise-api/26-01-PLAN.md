  <action>
1. Create `supabase/migrations/00013_api_keys.sql` with the full schema from the RESEARCH.md code example:
   - `api_keys` table (id UUID PK, org_id FK organisations, user_id FK auth.users, name TEXT, key_hash TEXT UNIQUE, key_prefix TEXT, last_used_at TIMESTAMPTZ, revoked_at TIMESTAMPTZ, created_at TIMESTAMPTZ DEFAULT NOW())
   - `webhook_endpoints` table (id UUID PK, org_id FK organisations, url TEXT, secret TEXT, events TEXT[] DEFAULT '{validation.completed,validation.failed}', active BOOLEAN DEFAULT TRUE, created_at, updated_at)
   - `webhook_deliveries` table (id UUID PK, endpoint_id FK webhook_endpoints, event TEXT, payload JSONB, status TEXT CHECK IN pending/delivered/failed, attempts INT DEFAULT 0, last_attempt_at, response_status INT, response_body TEXT, created_at)
   - Enable RLS on all three tables. Admin-only policies using existing `get_user_org_role(org_id) = 'admin'` pattern
   - Indexes on key_hash, org_id, endpoint_id, status

2. Create `src/lib/types/api-keys.ts` with TypeScript types:
   ```typescript
   export interface ApiKey {
     id: string
     org_id: string
     user_id: string
     name: string
     key_prefix: string
     last_used_at: string | null
     revoked_at: string | null
     created_at: string
   }
   export interface ApiKeyCreateResult {
     key: string      // raw key, shown once
     prefix: string
     id: string
   }
   export interface WebhookEndpoint {
     id: string
     org_id: string
     url: string
     events: string[]
     active: boolean
     created_at: string
     updated_at: string
   }
   export interface WebhookDelivery {
     id: string
     endpoint_id: string
     event: string
     payload: Record<string, unknown>
     status: 'pending' | 'delivered' | 'failed'
     attempts: number
     last_attempt_at: string | null
     response_status: number | null
     created_at: string
   }
   ```

3. Create `src/lib/api-auth.ts` following the RESEARCH.md Pattern 1 exactly:
   - `resolveApiKey(request: Request): Promise<ApiKeyResult | null>` that:
     - Extracts `Authorization: Bearer tk_...` header
     - Hashes the raw key with SHA-256 using Node.js `crypto`
     - Looks up hash in `api_keys` table (service role client) where `revoked_at IS NULL`
     - Verifies the key owner's profile has `plan = 'enterprise'`
     - Updates `last_used_at` timestamp
     - Returns `{ orgId, userId, keyId }` or null
   - Export `ApiKeyResult` interface

4. Create `src/lib/api-rate-limit.ts` following RESEARCH.md Pattern 4:
   - In-memory Map-based sliding window: 100 requests/minute per key
   - `checkRateLimit(keyId: string): { allowed: boolean; remaining: number }`
   - Auto-reset window after expiry

1. Create `src/lib/actions/api-keys.ts` with server actions:
   - `generateApiKey(name: string)`: Auth check via getUser(), requireOrgRole(admin), verify profile.plan === 'enterprise' (return error if not), generate `tk_` + 32 random bytes hex, hash with SHA-256, store hash + prefix (first 11 chars) in api_keys table, return `ApiKeyCreateResult` with raw key. Use `crypto.randomBytes(32).toString('hex')` for key generation.
   - `listApiKeys()`: Auth check, requireOrgRole(admin), select from api_keys where org_id matches, order by created_at desc, return ApiKey[] (never return key_hash)
   - `revokeApiKey(keyId: string)`: Auth check, requireOrgRole(admin), update revoked_at to NOW() where id = keyId and org_id matches

2. Create `src/app/api/api-keys/route.ts` as a thin wrapper if needed for client fetching, or rely on server actions only. Prefer server actions pattern (consistent with project).

3. Create `src/components/settings/api-keys-section.tsx`:

   - Key list table: columns = Name, Prefix (tk_xxxxxxxx), Created, Last Used, Status (Active/Revoked), Actions (Revoke button)
   - Revoke button with confirmation dialog
   - If user plan is not enterprise, show an upgrade prompt instead of the key management UI
