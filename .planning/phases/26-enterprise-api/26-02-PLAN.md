<task type="auto">
  <name>Task 1: Upload and validate endpoints</name>
  <files>src/app/api/v1/upload/route.ts, src/app/api/v1/validate/route.ts</files>
  <action>
Create a shared helper pattern used by all v1 endpoints. Each endpoint follows this flow:
1. `resolveApiKey(request)` -- 401 if null
2. `checkRateLimit(apiKey.keyId)` -- 429 if not allowed, include `X-RateLimit-Remaining` and `Retry-After` headers
3. Business logic with org-scoped queries using service role Supabase client + `.eq('org_id', apiKey.orgId)` filter

**POST /api/v1/upload/route.ts:**
- Accept `multipart/form-data` with fields: `file` (required), `project_id` (required), `job_id` (required)
- Use `request.formData()` to extract the file
- Verify the project belongs to apiKey.orgId (service role client, query projects table with org_id filter)
- Verify the job belongs to the project
- Upload file to Supabase Storage using the same pattern as the existing upload flow: `{userId}/{datasetId}/{filename}` path
- Create a dataset record in the datasets table with status 'uploaded', file metadata, job_id
- Return 201 with `{ dataset_id, filename, status: 'uploaded' }`
- Error cases: 400 (missing fields), 401 (bad key), 403 (project not in org), 413 (file too large)

**POST /api/v1/validate/route.ts:**
- Accept JSON body: `{ dataset_id: string, config?: ProfileConfig }`
- Verify dataset belongs to apiKey.orgId by joining dataset -> job -> project -> org_id
- Update dataset status to 'validating' (same pattern as existing validate route)
- Proxy to FastAPI `POST /api/v1/validate` with `{ dataset_id, config }` body
- Return 202 with `{ dataset_id, status: 'validating', message: 'Validation started' }`
- Error cases: 400 (missing dataset_id), 404 (dataset not found or not in org)
  </action>

  </verify>
  <done>Upload endpoint accepts multipart file with API key auth and creates dataset record. Validate endpoint triggers validation via FastAPI proxy. Both enforce org scoping.</done>

<task type="auto">
  <name>Task 2: Results and reports endpoints</name>
  <files>src/app/api/v1/results/[runId]/route.ts, src/app/api/v1/reports/[runId]/route.ts</files>
  <action>
**GET /api/v1/results/[runId]/route.ts:**
- Follow the exact pattern from RESEARCH.md code example
- Resolve API key, check rate limit
- Fetch validation_run by runId with nested join: `validation_runs -> datasets -> jobs -> projects` to get org_id
- Verify `projects.org_id === apiKey.orgId`, return 404 if not
- Fetch all validation_issues for the run, ordered by row_number
- Return structured JSON matching this schema:
  ```json
  {
    "run_id": "uuid",
    "dataset_id": "uuid",
    "status": "completed",
    "total_issues": 42,
    "critical_count": 3,
    "warning_count": 15,
    "info_count": 24,
    "pass_rate": 87.5,
    "created_at": "ISO8601",
    "issues": [
      { "row_number": 1, "column_name": "KP", "rule_type": "range_check", "severity": "warning", "message": "...", "expected": "0-100", "actual": "150.2" }
    ]
  }
  ```
- Include `X-RateLimit-Remaining` header

**GET /api/v1/reports/[runId]/route.ts:**
- Resolve API key, check rate limit
- Fetch validation_run, verify org ownership (same join pattern as results)
- Accept query param `mode=executive|technical` (default: technical)
- Proxy to FastAPI `GET /api/v1/report/pdf/{runId}?mode={mode}` using FASTAPI_URL env var
- Stream the PDF response back with correct headers: `Content-Type: application/pdf`, `Content-Disposition: attachment; filename="truqc-report-{runId}.pdf"`
- Return the PDF bytes from FastAPI response
