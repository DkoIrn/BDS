    - Test: POST /certificates/{id}/revoke on already-revoked cert returns 404
    - Test: GET /certificates/{id}/verify returns {status: 'active', ...details} for valid cert
    - Test: GET /certificates/{id}/verify returns {status: 'revoked', revoked_at, revocation_reason} for revoked cert (no dataset details)
    - Test: GET /certificates/{id}/verify returns {status: 'not_found'} for unknown ID
  </behavior>
  <action>
    1. Create/extend `backend/app/routers/certificates.py`:

    **POST /certificates/{cert_id}/revoke** (authenticated, admin-only):
    - Accept optional `reason` field in request body (Pydantic model: RevokeRequest with reason: str | None = None)
    - Update certificates table: set status='revoked', revoked_at=now(), revoked_by=current user, revocation_reason=body.reason
    - Filter: .eq("id", cert_id).eq("status", "active") so already-revoked certs return 404
    - Return {"status": "revoked", "revoked_at": timestamp}
    - RLS enforces admin-only at DB level, but also check role in endpoint for clear error messages

    **GET /certificates/{cert_id}/verify** (public, no auth required):
    - Use service role Supabase client (bypasses RLS for public reads)
    - Select only public-safe fields: id, dataset_name, validated_at, rules_applied, issue_count, pass_rate, hmac_hash, org_name, status, revoked_at, revocation_reason
    - If not found: return {"status": "not_found"} with 200 (not 404 — prevents enumeration timing)
    - If active: return full details with status "active"
    - If revoked: return only id, status, revoked_at, revocation_reason (no dataset details per user decision)
    - Set Cache-Control: no-store to prevent stale verification results

    2. Register router in backend/app/main.py if not already registered.
