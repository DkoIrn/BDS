Replace the placeholder stage-review.tsx with the full implementation. This is a large component (~400 lines) so structure it with clear sub-components.

**Props interface:**
```typescript
interface StageReviewProps {
  state: PipelineState
  dispatch: React.Dispatch<PipelineAction>
  validationIssues: ValidationIssue[]
}
```

**Issue ID generation** -- stable deterministic IDs:
```typescript
function getIssueId(issue: ValidationIssue, index: number): string {
  return `${issue.type}-${issue.row ?? 'x'}-${issue.column ?? 'x'}-${index}`
}
```
IMPORTANT: This MUST match exactly the same function used in pipeline-workflow.tsx (Plan 01) for acceptedIssues filtering.

**Component state (useState):**
- `activeSeverity: "all" | "critical" | "warning" | "info"` -- severity filter tab
- `selectedIds: Set<string>` -- selected issue IDs for bulk
- `rejectingId: string | null` -- which issue has the inline reject comment open
- `rejectJustification: string` -- text for inline reject field
- `bulkRejectOpen: boolean` -- whether bulk reject dialog is open
- `bulkRejectJustification: string` -- shared justification for bulk reject

**Computed values (useMemo):**
- `issuesWithIds`: Map each ValidationIssue to `{ issue, id: getIssueId(issue, index) }`
- `filteredIssues`: Filter by activeSeverity
- `severityCounts`: Count per severity for tab badges
- `progress`: `{ total, reviewed, accepted, rejected, deferred }` computed from triageDecisions
- `isComplete`: reviewed >= total
- `progressPercent`: Math.round((reviewed / total) * 100)

**Layout structure:**

1. **Completed/skipped states** (like stage-clean.tsx pattern):
   - If `state.stages.review.completed`: show summary card with decision counts, "Continue to Clean" button
   - If `state.stages.review.skipped`: show "Review Skipped" card with "Continue to Clean" button

2. **Progress bar section** (top of active state):
   - Full-width rounded bar showing progressPercent
   - Text: "Reviewed: {reviewed}/{total} issues -- {accepted} accepted, {rejected} rejected, {deferred} deferred"
   - Use green fill for the progress bar

3. **Severity filter tabs**:
   - Horizontal row of buttons: All ({total}), Critical ({count}), Warning ({count}), Info ({count})
   - Active tab gets primary styling, others get muted/outline
   - Use the severity colors from the project: red for critical, amber for warning, blue for info

4. **Issue table** -- NOT reusing IssuesTable (it uses server-side types). Build inline:
   - Table header row: checkbox (select all filtered), Type, Severity, Row, Column, Message, Status, Actions
   - Each row:
     - Left: Checkbox for selection
     - Type badge (colored by issue.type, similar to IssuesTable RULE_COLORS pattern but for client types: missing=slate, duplicate=orange, outlier=amber, kp_gap=violet, kp_monotonicity=violet)
     - Severity badge using getSeverityColor
     - Row number, column name, message (truncated with title tooltip)
     - Status badge if triaged: green "Accepted", red "Rejected", amber "Deferred" (using Badge component)
     - Right: Three inline action buttons (Check icon=accept, X icon=reject, Clock icon=defer)
       - If already triaged, show muted versions or allow re-triage (decisions are re-editable per user requirement)
     - Row styling: subtle left border and background tint based on decision:
       - Accepted: `border-l-2 border-l-green-500 bg-green-50/50 dark:bg-green-950/20`
       - Rejected: `border-l-2 border-l-red-500 bg-red-50/50 dark:bg-red-950/20`
       - Deferred: `border-l-2 border-l-amber-500 bg-amber-50/50 dark:bg-amber-950/20`

   - When Reject is clicked on a row:
     - Set `rejectingId` to that issue's ID
     - Show inline text input below the row (not a modal) with placeholder "Reason for rejection (required)"
     - Two small buttons: Confirm (dispatches TRIAGE_ISSUE with reject + justification) and Cancel
     - Confirm is disabled if justification is empty
     - On confirm: dispatch, log audit, clear rejectingId

   - Accept and Defer actions: dispatch immediately with null justification, log audit

5. **Action buttons** (bottom):
   - Back button: `dispatch({ type: "GO_TO_STAGE", stage: "validate" })`
   - "Complete Review" button (primary): enabled only when isComplete, dispatches REVIEW_COMPLETE
   - Skip button: `dispatch({ type: "SKIP_REVIEW" })`. Show as outline button with text "Skip Review". If any issues exist, add a subtle warning: "(X issues not reviewed)"

**Audit logging:**
- Individual actions: `logAuditClient({ action: "triage.accept"|"triage.reject"|"triage.defer", entityType: "dataset", entityId: state.datasetId ?? undefined, metadata: { issueId, issueType, row, column, decision, justification } })`
