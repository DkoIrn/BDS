1. Create `onboarding-welcome.tsx` -- "use client" component:
   - Props: `{ onStart: () => void, onSkip: () => void }`
   - Full-screen overlay (fixed inset-0, bg-black/50, z-50) with centered Card
   - TruQC logo or ShieldCheck icon at top
   - Heading: "Welcome to TruQC"
   - Subtext: "See how TruQC catches survey data issues in under 3 minutes. We'll walk you through a real pipeline inspection with demo data."
   - Two buttons: "Start Guided Tour" (primary, calls onStart) and "Skip and Explore" (ghost, calls onSkip)
   - Clean design matching brand (use Tailwind, no new deps)

2. Create `onboarding-tooltip.tsx` -- "use client" component:
   - Props: `{ step: OnboardingStep, currentIndex: number, totalSteps: number, onNext: () => void, onSkip: () => void }`
   - Reuse the clip-path spotlight overlay pattern from `tutorial-overlay.tsx`:
     - Find target element via `document.querySelector(step.selector)`
     - Get bounding rect, render dark overlay with polygon cutout around target
     - Position tooltip card below/above the cutout based on available space
   - Tooltip card content: step.title (bold), step.description (text-sm), step progress ("Step 3 of 6")
   - Two buttons: "Next" (primary, calls onNext) and "Skip Tour" (ghost text, calls onSkip)
   - Use useEffect + ResizeObserver to reposition on window resize
   - If target element not found, render tooltip centered without spotlight

3. Create `onboarding-celebration.tsx` -- "use client" component:
   - Props: `{ issueCount: number, fixCount: number, onFinish: () => void }`
   - Full-screen overlay like welcome, with centered Card
   - Confetti-style heading: "Pipeline Complete!" with CheckCircle2 icon (green)
   - Stats row: "{issueCount} issues detected", "{fixCount} fixes applied", "All in under 3 minutes"
   - Subtext: "TruQC automates quality checks on your survey data. Upload your own files to get started."
   - Button: "Start Using TruQC" (primary, calls onFinish)

4. Create `guided-onboarding.tsx` -- "use client" component (the orchestrator):
   - Props: `{ user: { id: string; email: string }, onComplete: () => void }`
   - State: `tourPhase: "welcome" | "touring" | "celebration" | null`
   - State: `stepIndex: number` (current tooltip step, 0-5)
   - State: `demoState: PipelineState` managed by useReducer with pipelineReducer
   - Uses a SEPARATE sessionStorage key `truqc-pipeline-demo` (not the real pipeline key) to avoid state leakage
   - Flow:
     a. Shows `OnboardingWelcome` when tourPhase === "welcome"
     b. On "Start Tour": set tourPhase to "touring", auto-dispatch IMPORT_FILE with DEMO_DATASET.fileName
     c. For each stepIndex (0-5), show `OnboardingTooltip` with ONBOARDING_STEPS[stepIndex]
     d. On "Next" click: advance pipeline state for the CURRENT step, then increment stepIndex:
        - Step 0 (import): Already dispatched IMPORT_FILE. Next dispatches INSPECT_COMPLETE with DEMO_DATASET.
        - Step 1 (inspect): Dispatches VALIDATE_COMPLETE with DEMO_VALIDATION runId and issueCount.
        - Step 2 (validate): Dispatches REVIEW_COMPLETE (pre-fill triageDecisions from DEMO_TRIAGE first).
        - Step 3 (review): Dispatches CLEAN_COMPLETE with DEMO_CLEAN_RESULT, actionCount: 3.
        - Step 4 (clean): Dispatches SET_EXPORT_FORMAT with "csv".
        - Step 5 (export): Set tourPhase to "celebration".
     e. On celebration "Finish": call completeOnboarding() server action, set localStorage key "truqc-onboarding-completed" to "true", call onComplete prop.
     f. On any "Skip": call completeOnboarding(), set localStorage, call onComplete.
   - Renders the real pipeline stage components (read-only / demo mode) behind the tooltip overlay. Pass demoState to render the correct stage. Use the same stage components but with demoMode=true prop or by simply letting them render with the demo data.
   - IMPORTANT: Do NOT make any real API calls. All data is from pre-computed constants.

5. Add `data-onboarding` attributes to existing stage components:
   - `stage-import.tsx`: Add `data-onboarding="stage-import"` to the main upload dropzone container
   - `stage-inspect.tsx`: Add `data-onboarding="data-preview"` to the data preview table wrapper
   - `stage-validate.tsx`: Add `data-onboarding="run-qc"` to the Run QC button or validation section
   - `stage-review.tsx`: Add `data-onboarding="issue-triage"` to the triage panel container
   - `stage-clean.tsx`: Add `data-onboarding="fix-actions"` to the fix buttons section
   - `stage-export.tsx`: Add `data-onboarding="export-panel"` to the export options section

6. Modify `pipeline-workflow.tsx`:
   - Accept optional `demoMode?: boolean` and `onDemoComplete?: () => void` props
   - When `demoMode` is true, render `GuidedOnboarding` instead of the normal workflow
   - Add URL search param detection: if `?demo=true` is in URL, activate demo mode
   - When GuidedOnboarding calls onComplete, clear demo sessionStorage key, redirect to /pipeline (normal mode)
